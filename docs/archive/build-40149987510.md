## Device and runtime validation still required

The application and VPN extension now require iOS 26.0 (previously 27.0), enforced in every Xcode configuration and checked in the built bundle. The SDK and CI runner remain Xcode/iOS 27. CI uses the Xcode 27 runner and checks the installed iOS SDK.

Rendering follows current window geometry instead of a phone-model identifier. Fixed game resolutions survive window changes, including folded/unfolded layouts, without silently becoming native-display resolution. New profiles default to 960x540 / 30 FPS; explicit saved profiles remain unchanged. The DXMT D3D11 frame limiter is configured through its actual `d3d11.preferredMaxFrameRate` setting. No FPS-limit guarantee is made for D3D12 or D3D9.

JIT detection checks the process code-signing debug permission before attempting a second MAP_JIT region and refreshes while active. This addresses false-negative detection after debugger detach or when a JIT region already exists. It does not control StikDebug's background lifetime or prove that a reported game stop was caused by the debugger connection. Device logs from the time of an actual stop remain necessary to establish that cause.

Local verification: shell syntax, diff whitespace, and five Python bundle-verifier tests passed. The Swift host checks for profile settings and window fitting run in CI. iPhone Duo hardware behavior, GPU performance, native compilation and prolonged JIT sessions remain unverified.
